# UI 디자인 시스템 (IBM Carbon 기반)

> 마지막 갱신 2026-08-31

---

## 1. 무엇을 Carbon 에서 가져오고 무엇을 우리가 정하는가

| Carbon 에서 | 우리가 |
|---|---|
| 토큰 구조 (`$layer-01`, `$text-primary` …) | **색 전부** |
| 간격 스케일 (`$spacing-01`~`09`) | 한글 폰트 (Pretendard) |
| 타이포 스케일 | 상승/하락 방향 (한국 관행) |
| 그리드·브레이크포인트 | 데이터 등급 표시 규칙 |
| 컴포넌트 마크업·동작·접근성 | 화면 구성 |

**IBM 로고·상표·고유 문구는 쓰지 않습니다.**
Carbon 은 오픈소스 디자인 시스템이고, 우리가 쓰는 것은 그 구조입니다.

---

## 2. 패키지 — 왜 `@carbon/react` 가 아닌가

이 앱은 **Flask + Jinja2 서버 렌더링**입니다. React 앱이 아닙니다.

| 패키지 | 버전 | 씀? |
|---|---|---|
| `@carbon/styles` | 1.114.0 | ✅ 실제 컴포넌트 CSS + 토큰 |
| `@carbon/web-components` | 2.62.0 | 설치만 — 아래 참조 |
| `@carbon/react` | — | ❌ 프론트를 React 로 재작성해야 함 |

### web-components 를 설치하고도 안 싣는 이유

번들이 **1.2MB(gzip 139KB)** 입니다. 그런데 지금 화면에서 클라이언트 JS 가
필요한 곳이 없습니다.

| 요소 | 어떻게 |
|---|---|
| 보기 모드 전환 | 링크 (`?mode=easy\|expert`) — 서버 렌더 |
| 탭 | 링크 |
| 근거 펼치기 | 네이티브 `<details>` |
| 버튼·입력·태그·알림·스켈레톤 | **Carbon CSS 클래스** (`cds--btn` 등) |

아무 동작도 없는 페이지에 139KB 를 싣는 것은 느린 회선의 사용자에게
값을 치르게 하는 일입니다. 지도처럼 진짜로 JS 가 필요한 화면이 생기면
그때 `npm run build:js` 로 붙입니다 — 패키지는 이미 설치돼 있습니다.

```
static/css/app.css   391KB (gzip 37KB)   ← 지금 싣는 것
static/js/carbon.js  1.2MB (gzip 139KB)  ← 필요할 때만
```

## 3. 색

Carbon 의 IBM Blue(#0f62fe)를 쓰지 않습니다. 그대로 쓰면
"IBM 처럼 생긴 화면" 이 됩니다.

### 핵심색 — 짙은 남색

`styles/_brand.scss` 의 `$brand-700: #16365e` 가 기본 액션입니다.
흰 배경 대비 **9.1:1** — Carbon 의 본문 기준(4.5:1)을 넉넉히 넘습니다.

금융기관에서 오래 쓰인 색이라 신뢰로 읽히고, 부동산 화면의 빨강/파랑
(상승/하락)과 겹치지 않습니다.

### 상승 빨강 · 하락 파랑

미국식(상승 초록)과 반대입니다. 국내 사용자가 매일 보는 방향으로 맞췄습니다.

```scss
$rise-500: #c62828;   // 상승 (대비 5.9:1)
$fall-500: #1565c0;   // 하락 (대비 5.6:1)
```

**⚠ 색만으로 구분하지 않습니다.** `.delta--up` / `.delta--down` 이
`::before` 로 **▲ ▼** 를 항상 붙입니다. 색각 이상인 사람에게 빨강·파랑은
구분이 어렵습니다. 이건 선택이 아니라 Carbon 접근성 기준입니다.

## 4. 데이터 등급 (§5) — 절대 섞지 않는다

```
.grade--confirmed   실거래   초록   실제로 일어난 거래
.grade--listing     호가     주황   파는 사람이 부르는 값
.grade--estimated   추정     회색   우리가 만든 값
.grade--unknown     확인불가 빨강   0 이 아니다
```

실거래가와 매물호가를 하나의 가격처럼 합치지 않습니다. 색과 라벨 **둘 다**
로 구분합니다.

모든 숫자 아래에 `.provenance` 로 출처·기준일이 붙습니다.

---

## 5. 점수 (§6) — 종합점수만 크게 보여주지 않는다

`.score-set` 은 항상 세 값을 나란히 둡니다.

```
Expected Alpha  78     Risk  42     Confidence  83
```

Alpha 78 / Confidence 30 은 Alpha 40 과 **완전히 다른 상태**입니다.
하나로 합치면 그 구분이 사라집니다.

그 아래 `.factor-list` 가 점수를 올린/내린 요인을 가중치와 함께 보여주고,
`<details class="evidence">` 를 펼치면 산식과 원본 데이터가 나옵니다.

## 6. 반응형

| | PC (≥672px) | 모바일 |
|---|---|---|
| 비교표 | 가로 비교 · 항목 열 고정(sticky) | **세로 카드로 전환** |
| 점수 | 3열 | 1열 |
| 메뉴 | 전체 표시 | 가로 스크롤 |

모바일에서 `<td>` 가 `data-label` 로 단지명을 앞에 붙입니다 —
표 헤더가 사라져도 어느 단지 값인지 알 수 있어야 합니다.

## 7. 안 하는 것

- 과도한 그림자 — 카드 구분은 **1px 테두리로만**
- 그라데이션
- 불필요한 애니메이션 — `prefers-reduced-motion` 도 존중
- 색만으로 정보 전달

## 8. 빌드

```bash
npm install
npm run build          # CSS + JS
npm run build:css      # CSS 만 (평소엔 이것만)
npm run build:css:watch
```

산출물(`static/`)은 **커밋합니다.** Flask 를 돌릴 때 Node 가 필요 없게
하기 위해서입니다. `node_modules/` 는 gitignore 입니다.
