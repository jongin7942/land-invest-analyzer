## 1. 자동 수집 (data.go.kr)

`DATA_GO_KR_SERVICE_KEY` 가 필요하다. **제 실행환경에서는 차단돼 있어
종인님 PC 에서만 돌아간다.**

| 무엇 | 엔드포인트 | 명령 |
|---|---|---|
| 아파트 매매 실거래 | `RTMSDataSvcAptTradeDev` | `collect trades` |
| 아파트 전월세 실거래 | `RTMSDataSvcAptRent` | `collect rents` |
| K-apt 단지 목록 | `AptListService4/getSigunguAptList4` | `collect complexes` |
| K-apt 단지 기본정보 | `AptBasisInfoServiceV5/getAphusBassInfoV5` | 〃 |
| 좌표 (V-World) | `api.vworld.kr/req/address` | `geocode` |

### 엔드포인트 버전에 얽힌 사고

K-apt 는 V1~V5 · List2~4 가 공존한다. 한동안 **폐기된 버전을 부르고 있었고,
게다가 그 응답은 JSON 인데 파서가 XML 전용**이라 정상 응답을 빈 목록으로
처리했다. "API 가 아무것도 안 준다" 로 보였지만 실제로는 우리가 못 읽은
것이었다. 지금은 V5/List4 를 쓴다.

### 행정구역 코드

인천 개편(중구·동구 → 제물포/영종, 서구 → 서해/검단)을 반영했다.
그리고 처음에 **가정이 정반대였다** — "과거 거래는 옛 통합코드로 조회해야
한다" 고 봤는데, 실거래가 API 는 과거 데이터도 **현재 코드로 소급 재편해서**
준다. 폐지 코드로 조회하면 전 기간 0건이 나온다.

세율·규제를 코드에 적지 않기 위한 파일들이다. 값이 바뀌면 CSV 만 고친다.

### 시점별 versioning

모든 규칙에 `effective_from` · `effective_to` 가 있다. **기존 행을 고치지
않는다** — `effective_to` 를 채우고 새 행을 추가한다. 덮어쓰면 과거 시점
분석이 조용히 틀려진다.

`rules/*.csv` 의 시행일이 전부 최근이라 **2021년 물건을 분석하면 "규칙 없음 →
확인 불가" 가 나온다.** 자세한 것은 `loan_tax_versioning.md`.

## 3. 도메인 지식 입력 (사람이 넣어야 하는 것)

공개 API 로 안 오는 것들이다. 서식은 `<명령> template` 로 받는다.

| 무엇 | 명령 | 없으면 |
|---|---|---|
| 가격 사다리 | `ladder import` | Next Node · Money Arrival Depth 불가 |

| 평당 공사비 | `redev import cost` | 추가분담금 불가 |

## 4. 출처 등급 (§3)

같은 필드에 서로 다른 값이 오면 **덮어쓰지 않고 둘 다 남긴다**
(`source_conflict` 표). 공식 출처를 우선하되 진 값도 기록한다.

| 등급 | 무엇 |
|---:|---|
| 1 | 공식 정부/지자체 — 법령·고시·건축물대장·정비사업 고시 |
| 2 | 공식 공공데이터/API — 국토부 실거래가, K-apt, V-World |
| 3 | 공신력 높은 원천 — 한국부동산원, 감정평가, 조합 공고 |
| 4 | 민간 데이터 서비스 |
| 5 | 포털 |
| 6 | 기타 — 현장 확인, 중개사 구두 |

**등급이 같으면 자동으로 고르지 않는다.** `resolved_to=NULL` 로 두고
"사람이 확인하세요" 를 남긴다.

## 5. 합성 데이터 (실제 DB 에 들어갈 수 없음)

`backtest/synthetic.py` 가 만드는 시장은 **하네스 검증 전용**이다.

- `require_scratch()` 가 실제 DB 파일에 쓰는 것을 막는다
- 합성으로 학습한 가중치는 `market_source='SYNTHETIC'` 로 저장되고
  실전 랭킹은 `REAL` 만 읽는다
- 라벨에 항상 `⚠ 실제 시세가 아닙니다` 가 붙는다

한 번 섞이면 어느 행이 진짜인지 구분할 방법이 없다. 지우는 것보다 막는 게 싸다.
