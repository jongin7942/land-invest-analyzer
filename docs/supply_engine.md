# 공급 엔진 (지시서 §77·§13)

> 마지막 갱신 2026-08-31

---

## 1. 절대 물량이 아니라 비율

"3년 내 5,000세대 입주" 는 그 자체로 아무 뜻도 없다. 강남구에 5,000세대와
소도시에 5,000세대는 완전히 다르다.

```
SupplyRatio = 유효 공급량 ÷ 기존 재고
```

**재고(stock)를 모르면 절대물량으로 대체하지 않는다.** 비율을 못 내면
"확인 불가" 다. 대체하면 큰 지역이 무조건 안전해 보인다.

---

## 2. 단계 가중치 — 계획과 착공은 다르다

| 단계 | 가중치 |
|---|---:|
| 계획 | 0.25 |
| 분양 | 0.60 |
| 착공 | 0.85 |
| 입주예정 | 1.00 |
| 입주완료 | 1.00 |

계획 단계 물량은 절반 이상이 안 나온다. 그걸 1.0 으로 세면 공급 위험이
크게 과대평가된다. 반대로 착공한 물량은 거의 확실히 들어온다.

**이 가중치는 관측된 실현율이 아니라 판정 기준이다.** 백테스트가 실제
실현율로 대체한다(`STAGE_NOTE`).

---

## 3. 경쟁 관계 (§13)

같은 급의 공급이 가장 아프다.

| 분류 | 뜻 |
|---|---|
| 동급경쟁 | 비슷한 가격대·면적 — 직접 대체재 |
| 상급상품 | 더 비싼 신축 — 상단을 눌러 준다 |
| 하급상품 | 더 싼 물건 — 영향 작음 |

---

## 4. 공급 절벽 (§13)

물량이 **끊기는** 지점을 본다.

```
supply_cliff = 다음 구간 공급이 이전 구간 대비 절반 이하로 떨어지는가
```

절벽 뒤는 위험이 아니라 **기회**다. 그래서
`effective_supply_risk` 는 절벽이 확인되면 위험을 0.6배로 낮춘다.

---

## 5. 감점은 한 곳으로만 (§45)

전에는 `supply_ratio_1y/2y/3y/5y` 가 각각 ALPHA 모델과 Kill 규칙 양쪽에
흩어져 있었다. 같은 공급 신호가 여러 번 세어졌다.

지금은 **`effective_supply_risk` 하나로만** 감점이 나가고, 원시 비율들은
CONTEXT 로 내려갔다(점수에 직접 안 들어가고 이 값의 입력이 된다).

### 가장 임박한 위험을 쓴다

| 구간 | 가중 |
|---|---:|
| 1년 | ×1.00 |
| 2년 | ×0.70 |
| 3년 | ×0.40 |
| 5년 | ×0.15 |

알려진 항의 **가중 최댓값**을 쓴다. 가중평균을 쓰면 5년치 하나만 아는 후보가
1년치 하나만 아는 후보와 같은 위험이 된다(분모가 같이 줄기 때문). 그렇다고
모르는 항을 0 으로 채우면 위험이 과소평가된다. 최댓값이 둘 다 피한다.

**하나도 모르면 0 이 아니라 "확인 불가" 다.**

---

## 6. 컷오프 (§18)

`supply_plan` 은 `announced_ym` 으로 자른다 — "언제 알았나" 다.
`move_in_ym`(언제 들어오나)으로 자르면 미래 공급을 아예 못 보게 된다.

이 컬럼이 원래 **없었다.** `effective_from` 을 쓰는 코드를 썼는데 그런 컬럼이
없어서 마이그레이션 014 에서 추가했다.

---

## 7. 지금 상태

`supply_plan` 이 **비어 있다.** 입주물량은 공개 API 로 안 오고 수기 입력이다.

```bash
apt supply template rules/supply.csv   # 서식
apt supply import rules/supply.csv
```

없으면 공급 관련 Feature 가 전부 "확인 불가" 이고, EarlyAlpha 의 감점 항
하나(`EffectiveSupplyRisk`)가 빠진다.
