# 대출·세금의 시점 관리 (지시서 §77·§24·§25)

> 마지막 갱신 2026-08-31

세율과 규제는 바뀐다. 그런데 **바뀌었다는 사실보다 언제 바뀌었는지가 더
중요하다** — 2021년 물건을 2026년 세율로 계산하면 그 백테스트는 전부 거짓이다.

---

## 1. 원칙 — 덮어쓰지 않는다

모든 규칙 표(`tax_rule` · `loan_rule` · `cost_rule` · `regulation_zone` ·
`land_permit_zone`)에 두 컬럼이 있다.

```
effective_from    이 규칙이 시작된 날
effective_to      끝난 날 (NULL = 아직 유효)
```

값이 바뀌면 **기존 행을 고치지 않는다.**

```
① 기존 행의 effective_to 를 채운다
② 새 기간의 행을 추가한다
```

덮어쓰면 과거 분석이 **조용히** 틀려진다. 에러가 안 나고 숫자만 달라지기
때문에 알아채기 어렵다.

---

## 2. 조회는 시점을 반드시 받는다

```python
rules.lookup(conn, kind="취득세", as_of="2021-06-01")   # as_of 는 필수 인자
```

`as_of` 에 기본값이 없다. 빠뜨리면 `TypeError` 다. "오늘 기준" 을 암묵적으로
쓰다가 과거 분석에 현재 규칙이 섞이는 것을 막기 위해서다.

그리고 `last_verified` 가 없는 규칙은 `UnverifiedRuleError` 를 던진다.
**검증되지 않은 숫자로 조용히 계산하지 않는다.**

---

## 3. 두 축을 구분한다

한 규칙에 두 가지 다른 정보가 있다.

| 축 | 값 | 뜻 |
|---|---|---|
| `status` | ENACTED / ANNOUNCED / PROPOSED / EXPIRED | **제도**가 어디까지 왔나 |
| `verification` | VERIFIED / ESTIMATED / UNKNOWN / NEEDS_VERIFICATION | **우리 데이터**가 얼마나 확실한가 |

발표만 되고 시행 안 된 규제(ANNOUNCED)를 지금 적용하면 안 되고,
시행 중인데 우리가 값을 확인 못 한 것(ENACTED + NEEDS_VERIFICATION)은
"확인 불가" 로 나가야 한다. 둘은 다른 상태다.

**`status='ENACTED'` 인 것만 금액 계산에 들어간다.**

### 세금 (`rules/tax.csv` · 26행)

표로 못 담아서 `rate_formula` 에 식을 넣고, `eval()` 대신 **ast 화이트리스트**
로 제한 평가한다. 임의 코드가 실행될 수 없다.

## 5. 지금 막고 있는 것 — 과거 규칙이 없다

**이것이 §28·§29·§31 을 막고 있는 진짜 이유다.**

| 표 | 가장 이른 시행일 | 그 이전을 보려면 |
|---|---|---|
| 취득세·지방교육세 | 2026-07-01 | 그 시점 세법 행 추가 |
| LTV·스트레스DSR·절대한도 | 2025-10-16 | 〃 |
| DSR | 2022-07-01 | 2015~2021 행 추가 |

2021년 물건을 분석하면 이렇게 된다.

```
LTV 규칙 없음  →  대출 가능액 확인 불가
              →  실투자금 확인 불가
              →  Capital Gate 를 아무도 통과 못 함
              →  후보 0개
```

그리고 후보 0개는 **"보수적이라 통과" 로 잘못 읽힌다.** 그래서
`backtest sanity` 가 실거래뿐 아니라 **그 시점 대출 규칙 유무까지** 확인하고,
없으면 "판정 불가" 를 낸다.

```
2021-01-01 [REVERSE] 판정 불가 — 2021-01-01 시점에 유효한 대출 규칙이
없습니다. 그 상태로 돌리면 실투자금이 확인 불가가 되어 후보 0개가 나오고,
그걸 '보수적이라 통과' 로 읽게 됩니다
```

---

## 6. 규칙이 없을 때의 태도

**낙관적으로 추정하지 않는다.**

실제로 이 원칙을 어겼던 적이 있다. LTV 규칙이 없으니 "집값보다 많이 빌릴 수는
없다" 는 산술 상한만 남았고, 그 결과 2.49억 아파트의 필요 현금이 **0.04억**
으로 나왔다. 규제가 없는 게 아니라 우리가 모르는 것인데, 모르는 것이
"제한 없음" 이 된 것이다.

지금은 그 경우를 "확인 불가" 로 표시하고, 화면에 **대출 없이 필요한 현금**을
크게 쓴다.

## 7. 확인이 필요한 값

`docs_dev/02-확인필요-정책값.md` 에 전체 목록이 있다. 요약하면:

- 다주택 중과(8%·12%) 건의 지방교육세 산식
- 농어촌특별세 85㎡ 초과 — 조문(0.2%)과 생활법령 요약(취득세액×10%)이
  다르게 읽힌다. 7.5억 120㎡ 기준 **150만원 차이**
- LTV 비규제·생애최초·다주택
- 양도소득세·지방소득세 (없으면 ROE 가 안 나온다)
- 재산세·종부세·공정시장가액비율·장기보유특별공제 (없으면 IRR 이 안 나온다)
- 서울·경기 중개보수 조례

전부 `NEEDS_VERIFICATION` 으로 두고 **임의로 채우지 않았다.**
