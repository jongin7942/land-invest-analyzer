## 0. 개발 원칙 — LLM은 데이터 생성기가 아니다

| 원칙 | 상태 | 구현 |
|---|:--:|---|
| LLM이 숫자를 추측해 실제 데이터처럼 표시 금지 | ✅ | LLM 미사용. 승인된 범위는 `narrative/`(리포트 문장)뿐이고 아직 비어 있음 |
| 모든 숫자에 source / 기준일 / 조회시각 / 신뢰도 / 계산법 | ✅ | `trace.Calc` (inputs·formula·intermediates·evidence·grade) + `data_source`·`retrieved_at`·`confidence` 컬럼 |
| "없음"이 아니라 "확인 불가" / "조회 실패" | ✅ | `collection_log.status ∈ {OK, EMPTY, FAILED}` · 표본 0이면 스냅샷을 만들지 않음 · CLI가 "확인 불가"로 출력 |
| 오래된 캐시를 최신처럼 보여주지 않음 | 🟡 | `retrieved_at`·`as_of_ym`·`calculated_at` 저장·표시. **경과일 경고는 미구현** |

## 다음 작업 (PHASE 7) — 왜 여기가 병목인가

PHASE 3~6으로 **한 시점의 값**(실투자금·대표가격·상대가격·촉매·재건축 분담금)은 나온다.
남은 건 그걸 **시간축에 올리는 일**이다.

요구사항 26·29·30·31(보유기간 시나리오·수익률·Stress Test)이 없으면
매도 타이밍(32)도, 적정 매수가(33)도, 목표수익률 역산(34)도 만들 수 없다.
그래서 PHASE 7은 현금흐름 + Peak Equity + 세후 IRR 이고, 그 입력으로
재산세·종합부동산세·양도소득세 규칙(요구사항 25의 남은 3종)이 먼저 필요하다.
