## 6. Hard Gate 연결 위치

```
apt_engine/regulation/gate.py
  applies_to_buyer(target_scope, nationality)   ← 국적 판정
  evaluate(rules, nationality, purpose, coverage_status)
  evaluate_at(conn, lawd_cd, sido, as_of, nationality, purpose)

apt_engine/ranking/executable.py
  split(..., gates={complex_id: Decision})      ← 실행목록에서 제외
    → Split.pure          Gate 무시한 순수 매력 순위 (연구용)
    → Split.gate_blocked  무엇이 왜 막혔나
```

**아직 `delta_pipeline` 에 연결하지 않았습니다.** 내국인 대상 토허가
0건이고 커버리지가 INCOMPLETE 라, 지금 켜면 모든 내국인 후보가
NEEDS_CHECK 로 막힙니다. 지시서 §2 가 요구한 정직한 상태이긴 하지만
화면이 비므로, **서울·경기·인천 ALL_BUYERS 토허를 넣은 뒤** 켭니다.

## 8. 대출 계산에서 아직 null 인 입력값

## 9. 실투자금 CONFIRMED / NEEDS_CHECK

규칙 CSV 를 전부 넣어도 **NEEDS_CHECK** 입니다. 남은 항목:

- 중개보수 부가세 — 중개업자 과세유형 미입력
- 국민주택채권 — 시가표준액·당일 할인율 없음 (규칙 0건)
- 등기신청수수료 · 증명서발급 — 규칙 0건
- 법무사 보수 — 견적 없음 (근거 없는 추정치 금지)
- 대출 가능액 — 소득 미입력

`agent_vat_registered=True` 를 넘기면 부가세 하나는 확정됩니다.

## 짚어야 할 것 — 지시서 안의 긴장 하나

§11 테스트 1 은 내국인 × FOREIGN_ONLY → **PASS** 를 기대하고,
§2 는 "개별 확인 못 한 주소는 **NEEDS_CHECK**" 라고 합니다.
부평구는 외국인 규칙만 넣었고 내국인 일반 토허는 미수집이라 둘이 충돌합니다.

**사유를 코드로 구분해 둘 다 만족시켰습니다.**

```
외국인 규칙이 내국인을 막는가        → 절대 아니다 (test_1)
커버리지 COMPLETE 이면              → PASS         (test_1b, §11 충족)
커버리지 INCOMPLETE 이면            → NEEDS_CHECK  (test_1c, §2 충족)
                                      check_code = COVERAGE_INCOMPLETE
```

`Decision.not_applicable` 에 "이 규칙들은 당신에게 적용되지 않았습니다"
가 남아서, 화면에서 "외국인 토허구역이지만 내국인이라 해당 없음" 을
말할 수 있습니다.
