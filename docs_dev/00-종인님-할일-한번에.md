## ★ 먼저 — 무엇이 진짜로 막고 있나

**진짜 blocker 는 "수집" 하나뿐입니다.** 나머지는 정확도를 올리는 것이지
막는 게 아닙니다. 규칙 CSV 를 **하나도 안 넣은 상태**로 실제 확인했습니다.

| 무엇 | 규칙 0개일 때 |
|---|---|
| `leaders build` | ✅ |
| `today --price-only` | ✅ 후보 30 → 매수가능 13 → EXECUTABLE 5 |
| `backtest run` | ✅ COMPLETE · 68창 채점 |
| **가중치 학습 (HEURISTIC → BACKTESTED)** | ✅ |
| **CORE Feature 승격** | ✅ 4개 |
| `today` (STRICT 게이트) | ❌ 매수가능 0 |
| `backtest sanity` | ❌ |

### 그래서 수집 끝나자마자 이것부터 하세요

CSV 를 하나도 안 채우고 돌려도 됩니다.

```powershell
python -m apt_engine.cli init
python -m apt_engine.cli match
python -m apt_engine.cli snapshot
python -m apt_engine.cli leaders build
python -m apt_engine.cli backtest run --start 2006-01-01 --end 2026-01-01 `
       --horizon 2 --step 3 --run-key wf1 --price-only
python -m apt_engine.cli backtest weights --run-key wf1
python -m apt_engine.cli today --cash 3 --weights backtested --price-only
```

이것만으로 **가중치가 HEURISTIC 을 벗어나고 CORE Feature 가 정해집니다.**
이 프로젝트의 가장 큰 미검증 항목이 그때 해소됩니다.

그 다음에 아래 A~G 를 채우면서 `--price-only` 를 떼면 됩니다.

> `--price-only` 는 **전액 현금 매수 가정**입니다. 대출을 안 쓴다고 보는
> 것이라 후보가 실제보다 훨씬 좁게 잡힙니다. B-1·C-1 을 채우면 뗄 수 있습니다.

## C. 대출 한도

### C-1. LTV — 비규제 / 생애최초 / 다주택 / 처분조건 없는 1주택

받은 건 규제지역 무주택·처분조건부 1주택의 40% 뿐입니다.
나머지 조건에서는 **"집값보다 많이 빌릴 수는 없다"는 산술 상한만** 남습니다.

실제로 이것 때문에 2.49억 아파트의 필요 현금이 **0.04억**으로 나왔습니다.
→ `rules/loan.csv` 주석 1~3번

### C-2. ★ 과거 시점 정책 — 회귀 테스트(sanity)에만 필요합니다

**메인 백테스트와 가중치 학습은 이것 없이도 됩니다.**
이게 막는 것은 §28·§29·§31 회귀 테스트뿐입니다.

| 표 | 지금 가장 이른 시행일 | 필요한 것 |
|---|---|---|
| 취득세·지방교육세 | 2026-07-01 | 2015·2017·2019·2021·2023 시점 행 |
| LTV·스트레스DSR·절대한도 | 2025-10-16 | 〃 |
| DSR | 2022-07-01 | 2015~2021 행 |

왜 필요한가:
```
2021년 LTV 규칙 없음 → 대출 가능액 확인 불가 → 실투자금 확인 불가
→ Capital Gate 를 아무도 통과 못 함 → 후보 0개
→ 그게 "보수적이라 통과" 로 잘못 읽힘
```

지금 `backtest sanity` 를 돌리면 정확히 이렇게 나옵니다:
```
2021-01-01 [REVERSE] 판정 불가 — 그 시점에 유효한 대출 규칙이 없습니다
```

**기존 행을 고치지 말고 `effective_to` 를 채운 뒤 새 행을 추가**하세요.
덮어쓰면 과거 분석이 조용히 틀려집니다.

## 수집 완료 기준 — "끝났다" 를 어떻게 판정하나

**"수집 프로세스가 종료됐다" 와 "240개월이 확보됐다" 는 다릅니다.**

수집은 일일 한도 소진·API 오류·중단으로 언제든 도중에 끝납니다. 그런데
프로세스는 정상 종료하고, 화면에는 완료라고 뜹니다. 기존
`report gaps` 도 **DB 에 들어온 달들 안에서만** 공백을 찾기 때문에,
120개월만 받고 멈춰도 "공백 없음" 이라고 답합니다. 없는 8년을 없다고
말하지 못합니다.

그래서 **받아야 할 격자를 먼저 만들고 대조**합니다.

```
python -m apt_engine.cli coverage            # 수도권 전체 240개월
python -m apt_engine.cli coverage --sido 서울
python -m apt_engine.cli coverage --months 120   # 우선 10년만 볼 때
```

```
필요 격자 = 거래유형(매매·전월세) × 시군구 × 최근 240개월
          = 2 × 83 × 240 = 39,840칸
```

한 칸이 채워졌다는 증거는 `collection_log` 의 기록입니다.

| 상태 | 뜻 | 채워졌나 |
|---|---|---|
| `OK` | 받았고 거래가 있었다 | ✅ |
| `EMPTY` | 받았고 거래가 없었다 | ✅ **이것도 채워진 칸입니다** |
| `FAILED` | 받으려다 실패했다 | ❌ 재시도 대상 |
| `NEVER` | **물어보지 않았다** | ❌ |

`EMPTY` 와 `NEVER` 를 섞으면 안 받은 달이 조용히 '거래 없는 달' 로
둔갑합니다. 그래서 따로 셉니다.

이 검사가 통과하기 전까지 **투자점수와 백테스트는 잠정값**입니다.
`rank --save` · `backtest run` · `backtest weights` 를 돌리면 경고 배너가
뜹니다. 막지는 않습니다 — 탐색은 해 보셔야 하니까요. 다만 그 숫자로
로직을 고정하지는 마세요.

### 수집이 끝난 뒤 순서

`scripts/postprocess.ps1` 이 이 순서를 그대로 돌리고, **1~7이 통과해야만
8~10을 시작합니다.**

| 단계 | 무엇 | 명령 |
|---|---|---|
| 1·2 | 매매·전월세 240개월 완전성 | `coverage` |
| 3 | 지역·단지·월별 결측률 | `coverage` + `report unmatched` |
| 4 | 비정상 0건 구간 탐지 | `coverage` |
| 5 | 중복·취소거래·이상치 | `validate` |
| 6 | 개편 전후 코드 연결 | `coverage` |
| 7 | 품질 리포트 | `logs\quality_report.txt` |
| 8 | 투자점수 | `rank --save` |
| 9 | 백테스트 | `backtest run` |
| 10 | 로직 보정 | `backtest weights` |

4번(0건 구간)은 지역마다 기준이 다릅니다. 옹진군에 한 달 아파트 거래가
없는 것은 흔하고, 강남구는 그럴 수 없습니다. 그래서 **그 지역이 평소 몇
건이나 나오는가**를 먼저 보고, 꾸준히 나오던 지역이 갑자기 0건일 때만
의심합니다. 절대 건수로 자르면 시골 군이 전부 오탐이 되고, 아예 안 보면
수집 실패를 놓칩니다.

## 화면 (새로 바뀐 것) — 종인님이 하실 일은 **없습니다**

화면을 IBM Carbon 기반으로 새로 만들었습니다. **Node 없이 그냥 돌아갑니다** —
빌드 산출물(`static/css/app.css`)이 저장소에 들어 있어서 평소처럼
`python apt_app.py` 만 하면 됩니다.

```
python apt_app.py       →  http://localhost:5001
```

새 화면 두 개가 생겼습니다.

| 메뉴 | 하는 일 |
|---|---|
| **비교** | 단지 검색에서 "비교에 담기" 로 최대 5개를 담아 나란히 비교 |
| **투자결론** | ① 이 현금으로 살 수 있는가 ② 어느 것이 나은가 ③ 사지 않는 선택 |

오른쪽 위 **쉬운 비교 / 전문가 분석** 을 누르면 같은 화면이 두 방식으로 보입니다.
전문가 분석에서는 산식·출처·기준일·표본 수가 펼쳐집니다.

### 화면에 '확인 불가' 가 많이 보이는 것은 정상입니다

위 체크리스트의 규칙(취득세·중개보수·법무비·LTV)이 아직 안 들어가서입니다.
**못 구한 값을 0원으로 세지 않기 때문에** 그렇게 보입니다. 규칙을 넣으면
그 자리가 저절로 금액으로 바뀝니다. 화면을 고칠 필요는 없습니다.

### 스타일을 고칠 때만 Node 가 필요합니다

```
npm install
npm run build          # styles/ → static/css/app.css
```

## 친구들에게 링크 보내기

**볼 사람을 먼저 정합니다** (한 번만):

```
python -m apt_engine.cli invite add 철수 --note "고등학교 친구"
python -m apt_engine.cli invite add 영희
```

**링크를 엽니다**:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\share.ps1
```

그러면 **사람마다 다른 링크**를 만들어 화면에 찍어 줍니다.
그대로 각자에게 카톡으로 보내면 됩니다.

```
철수
https://xxxx.trycloudflare.com/?code=VrtCnXkdponH

영희
https://xxxx.trycloudflare.com/?code=VUOJjWTIvE2D
```

**나중에**:

```
python -m apt_engine.cli invite list          # 누가 몇 번 들어왔는지
python -m apt_engine.cli invite revoke 철수    # 철수만 끊기 (나머지는 그대로)
```

공용 비번 하나를 단톡방에 뿌리는 것과 다릅니다 — 하나가 새어 나가면
**그 한 명만** 끊으면 되고, 나머지 링크는 살아 있습니다.

- 이 PC 가 켜져 있는 동안만 열립니다. 끄면 링크도 죽습니다.
- **실행할 때마다 주소가 바뀝니다** — 매번 새 링크를 보내야 합니다.
  고정 주소가 필요하면 [`../docs/deploy.md`](../docs/deploy.md) 방법 B(클라우드).
- 수집이 도는 중에도 됩니다 (화면은 읽기 전용으로 DB 를 엽니다).

### 알아 두실 것

지금은 **순위가 잠겨 있습니다.** 링크를 받은 친구는 "순위는 아직 잠겨
있습니다" 화면을 봅니다. 지금 보여줘서 쓸모 있는 건 잠금과 무관한
쪽입니다 — 단지 검색 · 대표가격 · 실투자금 계산 · 단지 비교 · 데이터 현황.

순위까지 보여주고 싶으면 `-ShowRankings` 를 붙이세요. 다만 그 화면은
"가중치가 학습값이 아니라 투자 판단 근거가 아닙니다" 라고 스스로 밝히는
화면입니다. 제대로 된 순위는 수집 완료 → `backtest run` 이후입니다.

# ★ 2차 DELTA 로 새로 생긴 할 일 (H·I·J)

2차 업그레이드에서 **돈의 흐름 분리**와 **토허 Hard Gate** 를 넣었습니다.
둘 다 데이터가 있어야 켜집니다. 없으면 지금처럼 '확인 불가' 로 남습니다
(0 으로 채우지 않습니다).

## H. 토허 입력 ← **이걸 넣어야 Gate 를 켭니다** ★

지금 `land_permit_zone` 이 **0건**입니다. 그래서 토허 Hard Gate 를
파이프라인에 **아직 연결하지 않았습니다.**

이유가 중요합니다. Gate 는 "확인 못 한 것을 통과시키지 않습니다".
데이터가 0건인 채로 켜면 **모든 후보가 NEEDS_CHECK 로 막힙니다.**
안전한 쪽으로 막는 게 맞지만, 화면에 아무것도 안 나오게 됩니다.

그래서 순서가 이렇습니다.

```
① 종인님이 토허 구역을 입력       ← 지금 필요한 것
② 제가 gates 를 파이프라인에 연결
③ 비거주 투자에서 실거주 의무 구역이 자동으로 빠짐
```

넣을 것 (수도권에서 실제 지정된 곳만, 없으면 안 넣어도 됩니다):

| 필드 | 뜻 | 주의 |
|---|---|---|
| `lawd_cd` · `emd_name` | 시군구 · 동 | 동 지정이면 동까지 |
| `target_scope` | **내국인 / 외국인** | ⚠ 절대 혼동 금지 |
| `effective_from` · `effective_to` | 지정 시작·종료 | 끝을 반드시 적습니다 |
| `residence_duty_months` | 실거주 의무 개월 | **비면 NEEDS_CHECK** |
| `residence_grace_allowed` | 유예 가능 여부 | 확인된 경우만 1 |
| `source_url` · `last_verified` | 출처·확인일 | 비면 계산에 안 씁니다 |

```powershell
python -m apt_engine.cli rule template permit rules\permit.csv
# 채운 뒤
python -m apt_engine.cli rule import permit rules\permit.csv
```

> 인천 외국인 토허는 2026-08-20 공고로 2027-08-25 까지 연장됐고 이미
> 입력돼 있습니다 (A-1 해결). 여기서 채우실 것은 서울·경기 자치구
> 목록과 필지 단위 고시입니다.

## I. 지역 소득·고용 (선택 — 넣으면 좋아짐)

`region_income` 표가 새로 생겼습니다. **안 넣어도 엔진은 돕니다** —
Income Flow 가 '확인 불가' 로 남을 뿐입니다.

넣으면 "이 지역에 실제로 돈이 들어오고 있나" 를 판단할 수 있습니다.
안 넣으면 사다리 이동(서울이 비싸져 내려오는 돈)만 보게 됩니다.

| 지표 | 어디서 | 가중치 |
|---|---|---|
| 고용자수 | 통계청 사업체노동력조사 · KOSIS | 1.00 |
| 고소득일자리 | 지역별 임금 분포 | 0.90 |
| 사업체수 | KOSIS 전국사업체조사 | 0.70 |
| 평균소득 | 국세청 시군구별 | 0.70 |
| 산업단지가동 | 산업단지공단 | 0.50 |
| 성과급 | 뉴스 (한 해짜리라 낮게 봄) | 0.30 |

⚠ **출처와 기준일이 없으면 DB 가 INSERT 를 거부합니다.** 추정치를
넣으면 "삼성이 있으니 오른다" 는 이름값 점수가 되기 때문입니다(§49-3).

## J. 정비사업 단지의 주변 신축 가격 — **끝났습니다** ✅

새 API 가 필요 없었습니다. 준공연도(K-apt)·좌표(V-World)·가격(실거래)이
**이미 다 들어오고 있어서** 그걸로 찾도록 구현했습니다
(`apt_engine/redev/peer_new.py`).

종인님이 하실 일은 **좌표 채우기 하나**입니다.

```powershell
python -m apt_engine.cli geocode --limit 500
```

좌표가 없으면 같은 법정동 안에서만 찾습니다(시군구 전체로 넓히면
압구정 신축을 개포동 재건축의 기준으로 쓰게 됩니다).
