## ★ 먼저 — 무엇이 진짜로 막고 있나

**진짜 blocker 는 "수집" 하나뿐입니다.** 나머지는 정확도를 올리는 것이지
막는 게 아닙니다. 규칙 CSV 를 **하나도 안 넣은 상태**로 실제 확인했습니다.

| 무엇 | 규칙 0개일 때 |
|---|---|
| `leaders build` | ✅ |
| `today --price-only` | ✅ 후보 30 → 매수가능 13 → EXECUTABLE 5 |
| `backtest run` | ✅ COMPLETE · 68창 채점 |
| **가중치 학습 (HEURISTIC → BACKTESTED)** | ✅ |
| **CORE Feature 승격** | ✅ 4개 |
| `today` (STRICT 게이트) | ❌ 매수가능 0 |
| `backtest sanity` | ❌ |

### 그래서 수집 끝나자마자 이것부터 하세요

CSV 를 하나도 안 채우고 돌려도 됩니다.

```powershell
python -m apt_engine.cli init
python -m apt_engine.cli match
python -m apt_engine.cli snapshot
python -m apt_engine.cli leaders build
python -m apt_engine.cli backtest run --start 2006-01-01 --end 2026-01-01 `
       --horizon 2 --step 3 --run-key wf1 --price-only
python -m apt_engine.cli backtest weights --run-key wf1
python -m apt_engine.cli today --cash 3 --weights backtested --price-only
```

이것만으로 **가중치가 HEURISTIC 을 벗어나고 CORE Feature 가 정해집니다.**
이 프로젝트의 가장 큰 미검증 항목이 그때 해소됩니다.

그 다음에 아래 A~G 를 채우면서 `--price-only` 를 떼면 됩니다.

> `--price-only` 는 **전액 현금 매수 가정**입니다. 대출을 안 쓴다고 보는
> 것이라 후보가 실제보다 훨씬 좁게 잡힙니다. B-1·C-1 을 채우면 뗄 수 있습니다.

## ⚠ 순서가 중요합니다

```
1단계  수집이 끝날 때까지 기다림        ← 지금 여기
2단계  init (마이그레이션 016)          ← 수집 끝난 뒤에만!
3단계  CSV 채우기 (아래 A~D)
4단계  백테스트 → 랭킹
```

**2단계를 지금 하면 안 됩니다.** 마이그레이션은 쓰기라서 수집이 도는 중에
돌리면 락 충돌로 **수집이 죽습니다.** (한 번 겪으셨죠)

수집 진행 확인:
```powershell
python -c "import sqlite3,config; c=sqlite3.connect(f'file:{config.APT_DB_PATH}?mode=ro',uri=True); print(c.execute('SELECT COUNT(*), MIN(deal_ymd), MAX(deal_ymd) FROM trade').fetchone())"
```

매매가 끝나면 **전월세도 받아야 합니다.**
```powershell
python -m apt_engine.cli collect rents --months 240
```

전월세 0건이면 `downside_defense` · `jeonse_lead` · `jeonse_ratio` 가 전부
안 나오고, 그건 EarlyAlpha 의 곱셈 항 하나가 빈다는 뜻입니다.

## A. 기한이 걸린 것 ★

### A-1. 인천 토지거래허가구역 재지정 여부

`rules/permit.csv` 의 인천 외국인 토허 13건이 **2026-08-25 로 끝났습니다.**
지금 엔진은 그 지역을 "토허 아님" 으로 봅니다.

재지정됐다면 전세 승계 판단이 뒤집혀서 **실투자금 계산이 전부 틀립니다.**

- 재지정됐으면 → **새 기간의 행을 추가** (기존 행 수정 금지)
- 해제됐으면 → 그대로 두면 됩니다

## B. 실투자금을 '확정' 으로 만드는 것

지금은 전부 "예상 실투자금" 입니다. 아래 셋 때문입니다.

### B-1. 법무·등기 실비 3종 ← 이것만 채우면 일반세율 케이스가 '확정'

`rules/cost.csv` 에 주석으로 자리를 만들어 뒀습니다. `#` 만 지우고 값 입력.

| 항목 | 출처 |
|---|---|
| 등기신청수수료 | iros.go.kr 수수료규칙 |
| 증명서발급 | 정부24 |
| 국민주택채권 | 주택도시기금법 시행령 [별표] + 당일 할인율 |

### B-2. 다주택 중과 건의 지방교육세

취득세 8%·12% 건의 지방교육세 산식. 지금 CASE 4·5·6 에서 "확인 불가" 입니다.
→ `rules/tax.csv` 주석 1번

### B-3. 농어촌특별세 85㎡ 초과 산식

조문(0.2%)과 찾기쉬운생활법령 요약(취득세액×10%)이 **다르게 읽힙니다.**
7.5억 120㎡ 기준 **150만원 차이**입니다. 어느 쪽이 맞는지 확인 필요.

## C. 대출 한도

### C-1. LTV — 비규제 / 생애최초 / 다주택 / 처분조건 없는 1주택

받은 건 규제지역 무주택·처분조건부 1주택의 40% 뿐입니다.
나머지 조건에서는 **"집값보다 많이 빌릴 수는 없다"는 산술 상한만** 남습니다.

실제로 이것 때문에 2.49억 아파트의 필요 현금이 **0.04억**으로 나왔습니다.
→ `rules/loan.csv` 주석 1~3번

### C-2. ★ 과거 시점 정책 — 회귀 테스트(sanity)에만 필요합니다

**메인 백테스트와 가중치 학습은 이것 없이도 됩니다.**
이게 막는 것은 §28·§29·§31 회귀 테스트뿐입니다.

| 표 | 지금 가장 이른 시행일 | 필요한 것 |
|---|---|---|
| 취득세·지방교육세 | 2026-07-01 | 2015·2017·2019·2021·2023 시점 행 |
| LTV·스트레스DSR·절대한도 | 2025-10-16 | 〃 |
| DSR | 2022-07-01 | 2015~2021 행 |

왜 필요한가:
```
2021년 LTV 규칙 없음 → 대출 가능액 확인 불가 → 실투자금 확인 불가
→ Capital Gate 를 아무도 통과 못 함 → 후보 0개
→ 그게 "보수적이라 통과" 로 잘못 읽힘
```

지금 `backtest sanity` 를 돌리면 정확히 이렇게 나옵니다:
```
2021-01-01 [REVERSE] 판정 불가 — 그 시점에 유효한 대출 규칙이 없습니다
```

**기존 행을 고치지 말고 `effective_to` 를 채운 뒤 새 행을 추가**하세요.
덮어쓰면 과거 분석이 조용히 틀려집니다.

## G. 프로필 (1분)

```powershell
python -m apt_engine.cli profile set --name 종인 `
    --cash 3 --income 0.8 --rate 0.045 --home-count 0 `
    --region 인천 --lender 은행 --cash-hurdle 0.03
```

`--cash-hurdle` 이 **새로 생겼습니다.** 세후 현금 수익률입니다.
없으면 CASH 순위를 만들지 않습니다 — 0% 로 가정하면 현금이 항상 최악이 되어
§3(CASH 를 후보로) 자체가 무의미해지기 때문입니다.

```powershell
git pull
python -m apt_engine.cli init                    # 마이그레이션 016 (수집 끝난 뒤!)

python -m apt_engine.cli rule import tax  rules/tax.csv

python -m apt_engine.cli validate

python -m apt_engine.cli report unmatched --limit 100   # ← 결과 보내주세요

# 백테스트
python -m apt_engine.cli backtest plan --start 2006-01-01 --end 2026-01-01 `
       --horizon 2 --step 3 --train-frac 0.45 --val-frac 0.35
python -m apt_engine.cli backtest run  --start 2006-01-01 --end 2026-01-01 `
       --horizon 2 --step 3 --run-key wf1 --cash-hurdle 0.03
python -m apt_engine.cli backtest sanity          # 2017/2019/2021/2023
python -m apt_engine.cli backtest weights --run-key wf1

# 랭킹
python -m apt_engine.cli today --cash 3 --weights backtested --columns --frontier
```

> 이미 넣은 DB 면 해당 표를 먼저 비우세요.

그 전까지 나오는 TOP10 은 배관 검증 결과지 투자 판단 근거가 아닙니다.

## 화면 (새로 바뀐 것) — 종인님이 하실 일은 **없습니다**

화면을 IBM Carbon 기반으로 새로 만들었습니다. **Node 없이 그냥 돌아갑니다** —
빌드 산출물(`static/css/app.css`)이 저장소에 들어 있어서 평소처럼
`python apt_app.py` 만 하면 됩니다.

```
python apt_app.py       →  http://localhost:5001
```

새 화면 두 개가 생겼습니다.

| 메뉴 | 하는 일 |
|---|---|
| **비교** | 단지 검색에서 "비교에 담기" 로 최대 5개를 담아 나란히 비교 |
| **투자결론** | ① 이 현금으로 살 수 있는가 ② 어느 것이 나은가 ③ 사지 않는 선택 |

오른쪽 위 **쉬운 비교 / 전문가 분석** 을 누르면 같은 화면이 두 방식으로 보입니다.
전문가 분석에서는 산식·출처·기준일·표본 수가 펼쳐집니다.

### 화면에 '확인 불가' 가 많이 보이는 것은 정상입니다

위 체크리스트의 규칙(취득세·중개보수·법무비·LTV)이 아직 안 들어가서입니다.
**못 구한 값을 0원으로 세지 않기 때문에** 그렇게 보입니다. 규칙을 넣으면
그 자리가 저절로 금액으로 바뀝니다. 화면을 고칠 필요는 없습니다.

### 스타일을 고칠 때만 Node 가 필요합니다

```
npm install
npm run build          # styles/ → static/css/app.css
```
