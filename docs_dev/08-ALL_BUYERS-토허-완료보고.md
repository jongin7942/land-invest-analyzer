# 전유부 대지권 — 연결 완료

## 저장 위치는 이미 있었다

`unit_type.land_share_m2` · `land_share_source` 가 이미 있었습니다
(재건축 스크리닝이 쓰던 것). 새 테이블을 만들지 않았습니다.

## 추정값은 문을 열 수 없다 ← 핵심 설계

`apt_engine/regulation/land_share.py`

| 값 | 출처 | 6㎡ 초과 판정 |
|---|---|---|
| 45㎡ | 공시 | **초과** (허가대상) |
| 5㎡ | 공시 | **이하** (대상 아님) |
| 45㎡ | 추정 | **초과** — 닫는 쪽이라 안전 |
| 17㎡ | 추정 | 확인 필요 |
| 5㎡ | 추정 | **확인 필요** ← 문을 열지 않는다 |

비대칭인 이유: **추정이 틀렸을 때 방향이 다릅니다.** 위로 틀리면 허가를
받으면 되지만, 아래로 틀리면 **허가 없이 계약해서 무효**가 됩니다.
경계 근처는 추정이 아무리 커도 안 씁니다 — 기준의 3배(18㎡)를 넘어야
"확실히 초과" 라고 말합니다.

`source` 에 **'공시'** 가 들어가야 확정값으로 취급합니다. 출처를 안 적으면
추정과 구분되지 않고, 구분되지 않으면 문을 여는 데 쓰이게 됩니다.

## 대지권이 없으면 추정한다 (문은 안 열림)

    단지 대지면적 × (이 타입 전용면적 / 전체 전유면적합)

`complex.land_area_m2` 가 있으면 자동으로 나옵니다. 등기부 대지권과
다를 수 있어서 **허가대상 '초과' 판정에만** 쓰입니다.

## 넣는 법

```powershell
python -m apt_engine.cli landshare import --template   # 서식 보기
python -m apt_engine.cli landshare import 대지권.csv
python -m apt_engine.cli landshare status              # 입력 현황
python -m apt_engine.cli landshare show --complex-id 1234 --band 84
```

부동산공시가격알리미(realtyprice.kr) → 공동주택 공시가격 → 산정기초자료,
또는 공공데이터포털 '주택 공시가격 산정기초자료' 파일데이터.

> **대량 수집용 API 는 없습니다.** 공동주택가격정보 API(15124003)는
> 공시가격 위주고 대지권이 응답에 없습니다. 열람·파일데이터가 실질적인
> 경로라, 관심 단지부터 넣는 방식이 현실적입니다.

## 파이프라인 연결

`ranking/delta_pipeline.py` 의 `_permit_gates()` 가 후보마다 대지권을
읽어 Gate 를 겁니다.

**국적이나 실거주 계획을 안 받았으면 Gate 를 걸지 않습니다.** 걸면 전
후보가 NEEDS_CHECK 로 막히는데, 그건 "확인이 필요하다" 를 "아무것도 못
산다" 로 바꿔 말하는 것입니다. 대신 그 사실을 메모로 남깁니다.

```
run(conn, ..., nationality="KOR", occupancy_plan="NON_OCCUPANCY")
```

## 2. 치환하지 않고 이었습니다

옛 코드를 새 코드로 바꿔 적으면 두 가지가 동시에 깨집니다.

- 2026-03 에 중구 아파트를 산 외국인이 허가 대상이었는지 되짚을 수 없다
- 옛 코드로 저장된 데이터가 고아가 된다

그래서 **폐지 코드를 남기고 관계를 따로 적습니다.**

`region` — 폐지 코드가 `is_active=0`, `until_ym='202606'` 으로 남습니다.
`region_lineage` (마이그레이션 020) — 어느 코드가 어느 코드를 승계했는지.

### ⚠ `region_lineage` 를 `regions.LEGACY` 에 옮기면 안 됩니다

`LEGACY` 는 **수집할 때 어느 코드로 API 를 때릴지** 정합니다. 실거래가
API 는 과거 거래까지 현재 행정구역 코드로 소급 재편해서 돌려주므로,
폐지 코드를 거기 넣으면 그 구간 수집이 통째로 0건이 됩니다. 두 표는
목적이 반대라 `LEGACY` 는 비어 있는 것이 정상이고, 테스트가 이를
강제합니다.

## 3. 같은 지정을 두 파일에 적지 않았습니다

원지정(2025-08-26 ~ 2026-08-25)은 이미 `rules/permit.csv` 에 공공데이터포털
15103016(인천광역시 토지거래허가구역 현황) 기준으로 **신행정구역 코드로**
들어가 있었습니다. 공공데이터가 그렇게 발행돼 있습니다.

그래서 `rules/permit_foreign.csv` 는 **연장분만** 담습니다.

| 기간 | 파일 | 출처 |
|---|---|---|
| 2025-08-26 ~ 2026-08-25 | `permit.csv` (9행) | 공공데이터포털 15103016 |
| 2026-08-26 ~ 2027-08-25 | `permit_foreign.csv` (7행 → **9행**) | 국토교통부 2026-08-20 연장 공고 |

겹쳐 적으면 같은 규칙이 두 번 잡히고, 둘의 값이 어긋나는 순간 어느 쪽이
맞는지 말할 수 없게 됩니다. 이 중복 금지를 테스트로 못박았습니다
(`test_같은_지정을_두_파일이_중복으로_적지_않는다` — 각 구·각 시점에서
잡히는 규칙이 정확히 1건).

원지정 9행의 `residence_duty_months` 는 **비워 둡니다.** 원 고시에서
확인하지 못했고, 0 으로 채우면 "실거주 의무 없음" 이라는 없는 사실을
만들어 냅니다. 비어 있으면 그 기간 외국인 계약은 `NEEDS_CHECK` 로 막힙니다.

`permit.csv` 의 stale 한 메모("연장 여부 미확인 · 종인님 재확인 권장")는
연장이 확인됐으므로 갱신했습니다. 행 자체는 지우거나 코드를 바꾸지
않았습니다.

## 5. Hard Gate 작동 확인 (요구 7번)

| 구 | 외국인·비거주 | 외국인·실거주 | 내국인·비거주 |
|---|---|---|---|
| 제물포구 `28125` | **BLOCKED** | PASS_WITH_PERMIT | **PASS** |
| 영종구 `28155` | **BLOCKED** | PASS_WITH_PERMIT | **PASS** |
| 서해구 `28275` | **BLOCKED** | PASS_WITH_PERMIT | **PASS** |
| 검단구 `28290` | **BLOCKED** | PASS_WITH_PERMIT | **PASS** |

BLOCKED 사유는 실거주 의무 24개월. 내국인 PASS 는 "규칙이 없어서" 가

확인합니다 — 그러지 않으면 승계 규칙이 통째로 빠져도 초록입니다.

## 8. 남는 오차 — 옛 동구 구역

제물포구 = 옛 중구 내륙 **+ 옛 동구**. 동구는 외국인 토허로 지정된 적이
없으므로, 제물포구 전역에 거는 규칙은 옛 동구 땅에 대해 실제 지정보다
넓습니다. 국토부 공고가 "행정구역 변경을 반영하여" 제물포구로 지정한
이상 현재 데이터는 공고대로지만, 필지 단위 고시를 확보하면 좁혀야
합니다.

외국인 매수 게이트에서 넓은 쪽 오차는 "허가를 받으라" 로 끝나고, 좁은
쪽 오차는 허가 없는 계약 → **무효** 로 끝납니다. 그래서 확인 전까지는
넓은 쪽에 둡니다.

원지정이 공공데이터에 이미 제물포구 코드로 발행돼 있어, 옛 동구 코드로
저장된 물건도 전 기간 제물포구 지정으로 판정됩니다. 조용히 통과하지
않는다는 것만 테스트로 못박았습니다.
