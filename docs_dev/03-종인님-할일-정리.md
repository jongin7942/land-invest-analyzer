## C. 대출 한도를 정확하게 만드는 것

### C-1. LTV — 비규제 / 생애최초 / 다주택 / 처분조건 없는 1주택

받은 건 **규제지역 무주택·처분조건부 1주택의 40%** 뿐이다. 나머지 조건에서는
`LTV 한도` 가 확인 불가라, 엔진이 **담보가액(집값)** 을 산술적 상한으로만 쓴다.

> 담보가액은 정책이 아니라 "집값보다 많이 빌릴 수는 없다"는 산술이다.
> 실제 LTV 는 훨씬 낮으므로 **지금 실투자금은 실제보다 작게 나올 수 있다.**

`rules/loan.csv` 주석 1~3번의 `<value>` 만 채우면 된다.
비규제 LTV 는 지시문에 "70% → 40%" 라고 적혀 있었지만, 그 70% 를 현재 유효한
규칙으로 확인해 주시기 전까지는 넣지 않았다.

### C-2. 백테스트용 과거 정책 (나중에)

```bash
python -m apt_engine.cli collect rents  --months 240

```

> 이미 넣은 DB 에 다시 넣을 때는 해당 표를 먼저 비우세요.

### F-2. ★ 수집 기간을 60개월이 아니라 **가능한 최대**로 잡아 주세요

Phase 8 백테스트 하네스를 만들면서 알게 된 건데, **수집 기간이 백테스트의
가능/불가능을 그대로 결정합니다.**

보유기간을 검증하려면 서로 **겹치지 않는** 검증 구간이 3개는 있어야 합니다.
겹친 구간을 따로 세면 표본을 부풀리는 것이라 신뢰도가 가짜가 됩니다.

| 보유기간 | 검증 구간에 필요한 햇수 | 필요한 전체 데이터(60/20/20 기준) |
|---:|---:|---:|
| 2년 | 6년 | 30년 |
| 5년 | 15년 | 75년 |
| 10년 | 30년 | 150년 |

국토부 실거래 공개가 2006년부터라 최대 20년입니다. 그래서:

* **2년 랭킹** — 학습 비율을 줄이면(`--train-frac 0.45 --val-frac 0.35`)
  검증 가능합니다
* **5년·10년 랭킹** — 데이터가 아무리 많아도 **정식 검증이 불가능**합니다.
  TRAIN 구간의 IC 까지만 보고, 가중치는 heuristic 을 유지합니다.
  이건 제 구현의 한계가 아니라 데이터 길이의 한계라서, 감추지 않고
  리포트에 그대로 표시하게 해 뒀습니다.

**그러니 `--months 60` 이 아니라 최대치로 받아 주세요.** 60개월(5년)이면
2년 보유조차 검증할 수 없습니다. 240개월(20년)이면 2년 보유는 검증됩니다.

수집이 오래 걸리면 시군구 단위로 나눠서 여러 번 돌려도 됩니다
(같은 행은 UNIQUE 로 걸러집니다).

수집이 끝나면 이 순서로 돌려 주세요:

```bash
python -m apt_engine.cli backtest plan --start 2006-01-01 --end 2026-01-01 \
       --horizon 2 --step 3 --train-frac 0.45 --val-frac 0.35
# → "독립 관측 N개 · 충분/부족" 이 나옵니다. 부족하면 비율을 더 조정
python -m apt_engine.cli backtest run  --start 2006-01-01 --end 2026-01-01 \
       --horizon 2 --step 3 --run-key wf1
python -m apt_engine.cli backtest weights --run-key wf1
python -m apt_engine.cli rank --cash 3 --horizon 2 --weights backtested
```

마지막 줄이 성공하면 그때부터 랭킹에서 **"가중치 임시(heuristic)"** 딱지가
사라집니다. 그 전까지 나오는 TOP10 은 배관 검증 결과지 투자 판단 근거가 아닙니다.

## G. 도메인 지식 입력 (PHASE 4~6 이 이걸 기다린다)

코드는 다 됐고 값만 비어 있다. 급한 순은 아니지만, 넣는 만큼 분석이 깊어진다.

| 무엇 | 명령 | 없으면 |
|---|---|---|
| **가격사다리** | `ladder template/import` | 비교단지가 안 잡혀 상대가치 분석 불가 |
| 교통사업 단계 | `transit template/import` | 교통호재 확인 불가 |
| 입주물량 | `supply template/import` | 공급 분석 불가 |
| **대지면적**(건축물대장) | `redev template/import landarea` | 재건축 사업성 **전부** 불가 |
| 정비사업 단계 | `redev template/import project` | 재건축 단계·지연위험 확인 불가 |
| 평당 공사비 | `redev template/import cost` | 추가분담금 계산 불가 |
| 단계별 소요기간 | `redev template/import duration` | 사업기간이 "확인 불가" |

**G-1.** 가격사다리 서식(`ladder template`)에 종인님이 주신 4개 축(서남권·경부축·
안양권·서북권)이 들어 있는데 **부천·광교·동탄의 `lawd_cd` 가 비어 있다.** 채워주세요.

**G-2.** 재건축은 **상위 후보만** 조사하면 된다:
```bash
python -m apt_engine.cli redev screen --limit 100   # 1차 자동 선별
python -m apt_engine.cli redev mark "단지명" --status 조사중
```
1차는 연식·용적률·대지지분만 보고 금액은 만들지 않는다.
상위 50~100개만 건축물대장·정비계획을 수기로 채우면 된다.
