# 규칙 등록 — 교통 호재는 "어디와 이어지느냐"로 먼저 나눈다 (종인님 지시, 2026-09-06)

## 지시 원문 요지
지하철 개통은 호선별로 **결국 어디와 이어지느냐**가 크기 때문에 나눠서 봐야 한다.
GTX, SRT도 마찬가지다. 그렇게 나눈 **다음에** 파급력을 본다.

## 엔진에 적용할 규칙
1. `transit_project` / catalyst 의 교통 항목은 `kind`(GTX·지하철·철도·도로)만으로 묶지 않는다.
   노선 단위(`line_id`)로 나누고, 각 노선에 **연결 목적지 등급**(`destination_tier`)을 붙인다.
   - 등급 기준은 노선이 직결·환승 없이(또는 1회 환승으로) 닿는 **직장 중심지의 크기**다.
     예: 강남·여의도·서울역/광화문·판교 같은 1급 직장 중심지 직결 > 부도심 > 외곽 지선.
   - 등급 표는 평가일 당시 공개된 노선 계획(종점·정차역)으로 만들고, 사후 변경은 available_at 을 지킨다.
2. 파급력(알파·시차·priced-in)은 **등급별로 따로** 추정한다.
   - `catalyst/analogue.py` 의 선행사례 매칭은 같은 kind 에 더해 같은 `destination_tier` 안에서만 찾는다.
     (GTX-A 킨텍스 사례를 외곽 지선 신설역에 그대로 쓰지 않는다.)
   - 등급이 없는 "개통 예정"에는 가점하지 않고 `DESTINATION_TIER_UNKNOWN` 으로 표시한다.
3. 근거: 종인님 집값 형성 이론(수요 → 직장 근접 → 끼리끼리 → 교육환경). 직장 근접이 1순위이므로
   교통 호재의 가치는 "얼마나 큰 직장 중심지에 얼마나 빨리 닿게 되느냐"로 결정된다.

## 상태
- 규칙 등록(종인님 지시). 등급표·알파 추정은 아직 구현 전. 구현 시 MASTER_SPEC §14(옵션 엔진)와
  `apt_engine/catalyst/*` 를 이 규칙에 맞춰 고치고, 변경 이력에 남긴다.
